# 109 — Wave A: any countable row may bound a seek

Maintainer, 2026-08-24. Section 3a of plan 108, as an executable wave.
Independent of wave B — different machinery, neither waits on the other.

## What is true today

`lower.py:4654` recognises a trim bound that references row columns, and
then refuses it outside a fan-out:

    a trim bound may reference track-row columns only under a fan-out TO

Two unrelated restrictions live inside that one rejection.

1. **Which rows may bound one.** The check asks whether the alias is a
   `_RowBinding`, which covers track and chapter rows. A `VALUES` row or
   a `generate_series` row is neither, so it cannot carry a window — the
   reason those row sources are useless for slicing today.
2. **Where the result may go.** The fan-out `TO` was required because N
   windows are N inputs, and N inputs had nowhere to go but N files.
   `VARIADIC` removed that: `ffmpeg.concat(VARIADIC array_agg(...))`
   gathers them into one.

## The shape already exists

`want/images`' motion thumbnail compiles today to **five `-i` of the
same file, each with its own `-ss`/`-to`**, feeding one graph — because
it is written as five hand-copied branches. This wave does not invent
that shape. It lets five ROWS produce it instead of five branches.

That gives the wave its sharpest test: the row-driven query must compile
to **byte-identical argv** against the hand-written one, the same
standard table functions were held to.

## What changes

- **Any compile-time-countable row source may bound a window.** Widen
  the `_RowBinding` test at `lower.py:4648` to admit `generate_series`
  and `VALUES` rows. Nothing downstream is track-specific: the window
  still resolves to `Graph.input_trims[alias]`, one `-i` per row
  (`lower.py:5425`, `:5545`).
- **A fan-out `TO` stops being the only destination.** When the rows are
  gathered — a `VARIADIC` aggregate consuming them — no fan-out is
  needed. The rejection survives for the case it was actually written
  for: N windows reaching a single sink that does not gather, which
  still has no way to name its files. Its message must name both ways
  forward, gathering and fanning out.
- **Seek semantics are unchanged.** Per-input `-ss`/`-to`, ffmpeg
  skipping what it discards. No PTS handling is needed here and none
  should be added: each window is its own input, so its timestamps
  already start at zero. That is wave B's problem, not this one's.
- `docs/known_gaps.md` — "A CTE-keyed group cannot fan out" is adjacent
  but NOT this. Leave it; check whether its wording still holds and say
  so in the report rather than editing it.

## Recipes first

Into `docs/examples.md`, before any implementation:

1. **N clips from a parameter, into N files** — the fan-out that works
   today extended to a series-keyed window.
2. **N clips gathered into one** — the same windows reaching a single
   `ffmpeg.concat(VARIADIC array_agg(...))` sink. This is the recipe the
   wave exists for.

Both as ordinary `pgsql` blocks with their compiled command beneath,
generated by running the compiler. Never hand-type an ffmpeg command
line.

## Verification

- The gathered form's argv is byte-identical to the hand-written motion
  thumbnail's for the same count and length.
- A series-keyed window with no gathering and no fan-out `TO` is still a
  rejection, and its message names both ways forward.
- A descending or single-row series still behaves as plan 108 section 2
  specified.
- `ruff`, `mypy --strict`, and the unit tier stay green.
