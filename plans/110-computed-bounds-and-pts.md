# 110 — Wave B: computed bounds, and the PTS reset that must ride with them

Maintainer, 2026-08-24. Sections 3b and 3c of plan 108, as one wave.
Independent of wave A.

They ship together on purpose. 3b makes `trim` drivable for the first
time; 3c is the trap that becomes reachable the moment it is. Landing
one without the other ships the landmine this plan exists to describe.

## 3b — a computed value may bound a filter

`ffmpeg.trim(v, starti => f.duration / 2)` is refused today:

    FILTER_OPTION_TYPE: option 'starti' of filter 'trim' expects a
    string, got a COLUMN expression

The information needed to allow it is thrown away one layer earlier.
`registry.py:270` collapses ffmpeg's own option types into three:

    "duration": "str",

ffmpeg reports `starti`, `endi` and `durationi` as durations; sqlmpeg
files them under `str` beside `color` and `flags`, and by the time
`lower.py:9118` validates a value there is nothing left to distinguish
"a filename" from "a number of seconds".

The change:

- **`FilterOptionType` grows a `"duration"` member** (`registry.py:149`)
  and `_TYPE_MAP` stops flattening it.
- **A duration option accepts either.** A string still works —
  `'00:01:30'` and `'90'` are both legal ffmpeg durations and queries
  may already pass them. A number, or any compile-time-countable
  numeric expression, is now equally legal and is written as seconds
  through the spelling rule the seek times already share
  (`lower.py:5081`), so `90` and `-ss 90` agree to the digit.
- **Not countable is still a rejection**, with the same shape as every
  other: name the option, the filter and what was written.

Two consequences to handle rather than discover:

- `tests/data/reference_registry.json` records option types, so the
  snapshot changes. Regenerate with `scripts/gen_snapshot.py`; do not
  hand-edit it.
- Anything that switches on `FilterOptionType` must learn the new member
  — `mypy --strict` will find them. Check `prompt.py` in particular:
  the dialect prompt describes option types to a model, and a duration
  that accepts numbers should say so.

## 3c — the compiler resets PTS after a trim

`trim` preserves source timestamps. Two trims concatenated without
`setpts=PTS-STARTPTS` leave a gap the length of the first clip's offset;
one trim written to a file alone carries a lead-in of however far into
the source it began. Neither is an error — both are silently wrong
output, which is the kind of thing a compiler exists to prevent.

- **After every `trim`/`atrim` whose result is used, insert a PTS
  reset**, unless that path already carries one the author wrote.
- **The compiler picks the variant from the stream's type** — `setpts`
  for video, `asetpts` for audio. This is a type check it can already
  make on a node it is inserting itself, and it needs nothing from
  plan 111.
- **Follow `sqlmpeg/split.py`.** `insert_splits` is the precedent: a
  pure pass, `Graph` in and a new `Graph` out, never mutating its input,
  run from `compiler.py:113`. Do the same, and run it **before**
  `insert_splits` so the split pass sees the final topology.
- **`explain` shows the inserted node**, as it already shows inserted
  splits. The graph stays inspectable and the insertion stays
  overridable by writing one.

Wave A's form needs none of this — each window is its own `-i`, whose
timestamps start at zero. Do not add PTS handling there.

## Verification

- A computed `starti` compiles, and the emitted seconds match what the
  same value produces as an `-ss`.
- A query with an explicit `setpts` gets exactly one, not two.
- An audio path gets `asetpts`, a video path `setpts`, in one query
  carrying both.
- Concatenated trims actually play with correct timing — this one earns
  an exec-tier recipe, since the whole point is output a compile check
  cannot see.
- `ruff`, `mypy --strict`, and the unit tier stay green.
