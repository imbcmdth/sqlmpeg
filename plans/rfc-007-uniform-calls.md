# RFC-007 — One calling convention: the great de-tiering

Status: accepted 2026-08-16. BREAKING release (post-PyPI: ship as the
headline of the next minor with a migration section in the changelog).
Waves: 050 snapshot -> 051 uniform resolution -> 052 sqlmpeg namespace ->
053 surface migration (docs prose authored in-session per convention).

## The rule

Every filter call works the way ffmpeg's own filtergraph syntax works:

    <name>(<stream inputs...>, <positional options...>, <named options...>)

- Stream inputs first, count and types from the pad signature.
- Positional options bind in AVOption DECLARED order — exactly the order
  `ffmpeg -help filter=<name>` prints and exactly how `gblur=5:1` binds in a
  filtergraph. This is ffmpeg's contract, not ours; ffmpeg cannot reorder
  options without breaking its own positional syntax.
- Named options (`sigma => 5`) may follow positionals; no positional after
  a named (existing rule). `enable` stays a named-only framework option
  gated on the T flag.
- Values: literals per the existing rules; string-typed options accept
  ffmpeg expressions (this replaces the stdlib `expr` kind — it was always
  the introspected truth underneath).

## Three namespaces, one convention

- **bare name** — an ffmpeg filter (when the name is not Postgres grammar).
- **`ffmpeg.<name>`** — the same filter, collision-proof spelling; strictly
  filters, nothing else. Required for the census's eleven collided names,
  optional-and-explicit otherwise. Sources stay `FROM ffmpeg.<src>(...)`.
- **`sqlmpeg.<name>`** — ergonomic helpers and macros: things that expand
  to subgraphs no single filter provides. `sqlmpeg` joins `ffmpeg` as a
  reserved alias/view name. Same calling convention (positional in OUR
  documented order + named), small by design:
  - `sqlmpeg.delay(stream, seconds)` — video: the transparent-canvas
    format+tpad macro; audio: seconds->ms adelay. The composition primitive
    for timed overlays.
  - `sqlmpeg.blur_regions(f, x, y, w, h, sigma)` — crop->gblur->overlay,
    region named once.
  - `sqlmpeg.speed(f, factor)` — setpts=PTS/factor.
  Admission bar for future entries: "cannot be expressed as one filter
  call, and people keep asking."

## The stdlib is deleted

All 39 curated functions go. Their fates: most become the bare filter with
ffmpeg's real option order (`crop(f, out_w, out_h, x, y)` — note the ORDER
CHANGE from the curated x,y,w,h); sugar forms become expressions
(`scale(f, 'iw/2', -2)`); overload-only conveniences become named args
(`fade(f, t => 'out', st => 8.5, d => 1.5)`); the three macros move to
`sqlmpeg.`. The FUNCTIONS table, ParamKind, FuncSpec, VariantImpl,
named_target, tier-1-named-extras, and the expr-kind machinery are all
deleted. `docs/stdlib.md` is replaced by a short `docs/sqlmpeg-macros.md`.

## Offline compile: the reference snapshot replaces --portable

- `sqlmpeg/reference_registry.json` (vendored, versioned, regenerated by
  `scripts/gen_snapshot.py` from a pinned ffmpeg): the parsed
  -filters/-help data in the registry's cache format, stamped with the
  source ffmpeg version.
- Resolution: a real ffmpeg on PATH wins; otherwise the snapshot loads
  silently. No binary anywhere is no longer fatal — it is the snapshot.
- Golden tests, fuzzing, and CI lint compile against the snapshot
  EXPLICITLY (a compile_sql knob or env the tests set) for determinism;
  user compiles prefer the live binary.
- `--portable` is deleted from the CLI. `--no-probe` survives unchanged
  (probing is about files, not filters). A new `--reference` flag forces
  the snapshot when a live ffmpeg would otherwise win (the old
  "will this compile elsewhere" use case, now with a concrete referent).
- `prompt`: the base prompt renders from the snapshot (portable by
  construction); `--dynamic` renders from the live binary as today.

## Error surface consolidation

UDF_ARG_TYPE narrows to stream-argument problems (count/type against the
pad signature) plus sqlmpeg-macro signatures; option problems are uniformly
UNKNOWN_FILTER_OPTION / FILTER_OPTION_TYPE (positional options too — a
positional bound to an option validates as that option). SINGLE_OUTPUT_ONLY
finally leaves the enum? NO — wire-format stability, it stays reserved.
Docs recaptured where messages change.

## Migration surface (wave 053)

Goldens regen (option-name keys change in IR args for former stdlib calls);
cookbook recipes re-spelled and re-verified; README quickstart re-spelled
(PiP demo: volume/amix/overlay/scale survive nearly as-is — verify orders);
prompt rewritten (much shorter: the rule, the namespaces, the macro trio);
dynamic-filters.md largely absorbed into a new docs/filters.md; trimming/
errors touched where spellings appear. All prose in-session.

## Non-goals

Variadic array-consuming calls (still queued separately); multi-output
filters beyond the array-returning trio; changing the ffmpeg.* source
surface; renaming anything in the sink/input option tables (they are
sqlmpeg surface, already namespaced by position, and WITH (...) is not a
call).
